# 即用创作小助手

## 先看装没装好

每次使用先运行：

    python3 ~/.clipflow/app/scripts/clipflow.py guide

- **输出里有 `STATUS:` 行**：已经装好了。读完输出的说明再照着做，**不用再请用户同意安装，也不用重新安装**（即用客服更新了用户服务协议时，命令会返回 `need_consent`，照它的 NEXT 请用户看一下新协议）。用户大多不懂技术，跟用户说每条命令输出的 SAY 就够了，不用贴命令和终端输出，也不用逐步播报。
- **报「找不到文件」（No such file）**：还没装好，按下面的「安装」3 步做。刚把这个技能装进技能库时就是这种情况，不用等用户再开口，在同一轮里接着做。
- **有输出但没有 `STATUS:` 行**：装坏了。用户之前已经同意过，直接运行下面第 2 步的安装命令重装，再运行一次上面的命令。

你不能执行命令时，如实告诉用户：请先在豆包里切到「工作-云电脑」模式，再发一次安装话术。

# 安装

## 1. 先请用户同意用户服务协议

安装之前先请用户看一下用户服务协议。运行安装命令之前，在这一轮最后一条回复里把下面这段话发给用户，然后结束这一轮，等用户回复：

> 即用创作小助手帮你把选好的短剧剪成解说视频，经你确认后发布到你的账号，不会自己生产创作内容。你的账号登录只在你的豆包云电脑上，小助手不会保存你的账号密码等敏感信息。开始之前请先点开看一下[《即用创作小助手用户服务协议》](https://xld.jiaredou.com/clipflow-v3/plugin/terms)；同意的话回复我「同意」，不同意我就不安装，以后想用再跟我说一声就行。

协议要作为可点击的链接发：链接文字只写协议名，不要把网址单独贴出来，也不要把协议内容贴给用户。

用户明确回复同意（「同意」「确认」「可以」这类明确答复）后再往下做。用户有疑问就如实解答，再请用户确认；用户不同意或没有明确表态时不要安装，也不要劝说。同意协议只是基础授权：之后选剧、看方案、发布、发短信验证码，到了那一步照常等用户回复。

## 2. 运行安装命令

    python3 -c "import urllib.request as u;exec(u.urlopen('https://raw.githubusercontent.com/jiyong-ai/staff/main/install.py').read())" --terms-agreed 2

`--terms-agreed 2` 表示用户在安装之前已经同意了协议（上一节），照原样带上，不要去掉；装好后小助手就不会再让用户同意一遍。用户的安装话术末尾有「订单号:」。后面填了订单号时，加上 `--order "<订单号>"`，只填订单号本身，不要把整句话填进来；空着或还是 `__` 时不加这个参数，装好后再问用户。

这条命令只用 Python 自带的功能，不需要 pip。它会先确认是豆包云电脑、校验安装包的发版签名，校验不过就不安装。运行这条命令，不要改写它，也不要自己拼装安装文件。

## 3. 按输出继续

命令最后三行固定是 `STATUS: 状态码`、`SAY: 要转告用户的话`、`NEXT: 你接下来要做的事`。把 SAY 转告用户，再照着 NEXT 做。装好后按 NEXT 一步步做：要用户选剧、看方案、确认发布、发验证码的地方，SAY 会告诉你，等用户回复再往下；其余的（检查剪辑环境、装发布功能、剪视频）照着 NEXT 做就行。

用户大多不懂技术，转告时说 SAY 的意思就够了，不用逐条播报运行的命令、终端输出和文件路径；命令要重试这类你自己能处理的小问题，处理好再往下做。用户问起做了什么、装在哪里，如实回答。

没有输出 STATUS 这三行、或者报错退出时，把报错原文告诉用户，请用户联系即用客服。
